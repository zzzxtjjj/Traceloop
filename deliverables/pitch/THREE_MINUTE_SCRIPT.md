# TradeLoop 三分钟路演脚本

状态：离线 HTML 已生成；最终二维码、页面截图、计时记录和 PDF/PPT 导出仍待现场验收。

目标：在三分钟内演示两条证据驱动闭环，并如实说明模型、权限、规则和模拟数据边界。

## 0:00 至 0:20 问题与方案

讲述：跨境业务的问题不是缺少表格，而是报价、差评、任务和复检分散，结论很难回到原始证据。TradeLoop 把这些记录连接在同一个项目内，让每个重要结论可追溯、可审核、可验收。

页面：项目首页。

必须说清：今天使用模拟数据展示工作流。

## 0:20 至 1:05 报价证据链

操作：

1. 打开“报价决策”。
2. 展开一个供应商风险。
3. 指向原始报价字段、风险理由和待澄清项。
4. 展示负责人填写理由后确认，而不是系统自动选择。

讲述：价格、币种、MOQ、交期和付款条件由程序校验与比较；系统保留原始行 Evidence。缺少落地成本或贸易条款时显示待确认，不让模型补造。

验收：45 秒内完成，不现场重新导入文件。

## 1:05 至 2:20 差评到改进复检

操作：

1. 打开“差评改进”中的改进前批次。
2. 展开包装破损 Finding，展示评价 ID、原文和统计口径。
3. 展示人工审核后创建的任务。
4. 切到“任务与日报”，展示交付 Evidence 和人工验收。
5. 返回差评页，展示改进后批次的样本量、数量、占比变化和限制说明。

讲述：模型或规则只提出结构化问题发现，数量和比例始终由程序计算。任务必须有交付物并经人工验收。前后变化只能说明趋势，不能单独证明措施有效。

验收：75 秒内完成；页面记录必须在演示前准备好。

## 2:20 至 2:45 异常和安全

页面：预先准备的模型未配置或缺失关联状态。

讲述：模型失败时不写入半成品结论；评价没有订单、批次或供应商信息时明确显示缺失；访问码只负责第二道项目解锁，不能替代已经持久化的成员权限。本地用户选择仍不是生产登录认证。

## 2:45 至 3:00 结论

讲述：TradeLoop 的价值不是替人做决定，而是让跨岗位改进从原始证据出发，经过人工确认、任务交付和后续复检，形成可解释的业务闭环。

页面：两条工作流总览或项目首页。

## PPT 或 HTML 页序建议

1. 业务痛点和一句话方案。
2. 两条证据链总览。
3. 报价原始证据与人工决策截图。
4. 差评 Finding、任务验收和复检截图。
5. 异常处理、能力边界和项目二维码。

每页只保留一个结论，避免在三分钟内朗读大段文字。

## 失败恢复

- 页面加载失败：切回项目首页并刷新一次；仍失败则按运行手册重启 Streamlit。
- 模型未配置：明确展示规则降级，不临时粘贴密钥。
- 模型配置检查：只运行离线命令，现场不自动执行 `--live`。
- 数据导入失败：使用已预置的演示批次继续主流程，异常原因留到问答环节说明。
- 时间超限：删减解释，不删除能力边界和人工审核说明。
