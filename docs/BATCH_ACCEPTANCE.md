## 3. 两条端到端工作流

### A. 报价风险到人工验收

- [ ] 导入正常报价并核对币种、价格、MOQ、交期和付款条件。
- [ ] 风险结论能够回到原始报价字段或明确缺失项。
- [ ] 将待确认事项创建为任务，填写责任岗位、交付物和验收标准。
- [ ] 缺少交付物时不能完成任务。
- [ ] 提交交付证据后，由不同的人工审核者接受或驳回。
- [ ] 从报价风险可以追溯到任务、交付物和验收记录。

### B. 差评到改进复检

- [ ] 导入首批评价并显示总数、分类、占比、时间范围和样本限制。
- [ ] 打开 Finding，查看评价 ID、原文引用、缺失信息和原因假设。
- [ ] 人工接受、修改或驳回 Finding 后创建改进任务。
- [ ] 提交交付证据并完成人工验收。
- [ ] 导入下一批评价，以一致口径显示样本量和前后变化。
- [ ] 可以从一条差评追溯到原文、任务、验收和复检。
- [ ] 页面没有把评价占比称为故障率，也没有单凭变化宣称因果有效。

## 4. 异常与安全检查

- [ ] 报价缺字段：导入停止，不创建半成品批次。
- [ ] 混合币种：系统阻止无依据的直接排名。
- [ ] 重复评价：不重复计数，不创建重复记录。
- [ ] 缺少订单/批次/供应商：显示待确认，不生成虚假关联。
- [ ] 正确访问码但非成员：仍被 `require_project_member` 拒绝。
- [ ] 普通成员不能添加成员；owner 可以添加。
- [ ] 重复成员、停用用户和停用成员均被拒绝。
- [ ] 拒绝信息不泄露项目名称、用户信息、对象 ID、上游响应或本地路径。
- [ ] 模型未配置、超时、鉴权、限流、坏结构时，数据保留且关键状态不写入伪成功。
