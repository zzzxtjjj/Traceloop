# TradeLoop 演示运行手册

本手册用于在新电脑上启动 TradeLoop，并稳定演示“报价到人工验收”和“差评到改进复检”两条证据驱动工作流。仓库中的客户、订单、供应商、评价和批次数据均为模拟数据；当前 AI 分类默认使用透明的规则基线，真实模型供应商尚未配置，不得在路演中表述为真实 AI 已上线。

## 1. 演示前检查

负责人：乙准备页面、数据和台词；甲确认数据库结构、`scripts/seed_demo.py` 和后端状态。

```powershell
cd D:\hackson
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
python scripts\seed_demo.py
python -m pytest -q
python -m ruff check core services pages scripts tests
streamlit run app.py
```

浏览器地址通常为 `http://localhost:8501`，演示项目访问码为 `demo2026`。

开始路演前逐项确认：

- [ ] `git status --short` 没有意外修改。
- [ ] 测试和 Ruff 均通过。
- [ ] 首页、项目首页、报价决策、任务与日报、差评改进、本地化与校验均可打开。
- [ ] 演示项目可以使用 `demo2026` 进入。
- [ ] 浏览器缩放、投影分辨率和网络状态已确认。
- [ ] 已准备离线规则降级说明，不把模型未配置说成模型成功。

## 2. 三分钟主演示路线

三分钟版本只展示价值链，不在现场逐项解释所有异常。

### 0:00 至 0:25 证据工作台

进入项目首页，说明 TradeLoop 把报价、评价、问题、任务、交付物和复检结果放在同一个项目上下文中。强调程序负责统计和规则检查，关键结论需要人工确认。

### 0:25 至 1:15 报价证据链

1. 进入“报价决策”。
2. 选择已有模拟报价批次，或导入 `data/demo/supplier_quotes.csv`。
3. 展示确定性排名、原始报价行 Evidence、风险提示和待澄清问题。
4. 说明排名不是自动选择供应商；负责人必须填写理由后确认。
5. 从已审核 Finding 创建澄清任务，展示任务需要交付材料和人工验收。

验收点：风险能回到原始报价字段；系统不补造缺失的成本、贸易条款或供应商事实。

### 1:15 至 2:35 差评改进闭环

1. 进入“差评改进”。
2. 导入 `data/demo/reviews_before.csv` 并运行主题分析。
3. 打开包装破损 Finding，核对评价 ID、CSV 行号、原文引用和缺失关联。
4. 人工接受或修改 Finding，再创建并发布改进任务。
5. 在“任务与日报”提交交付 Evidence，由负责人验收。
6. 导入 `data/demo/reviews_after.csv`，按相同口径比较前后批次。
7. 展示样本量、数量、占比变化和“变化不证明因果”的限制说明。

验收点：结论可追溯到评价原文；任务完成必须有交付物和人工验收；复检不能被描述为已证明改进有效。

### 2:35 至 3:00 边界和交付

说明以下边界：演示数据为模拟数据；当前模型提供器尚未配置，规则分类会明确标记；访问码和演示角色不是企业级身份系统；规则检查不是法律意见或平台最终审核。

## 3. 完整工作流 A 报价到人工验收

1. 进入项目并打开“报价决策”。
2. 导入 `supplier_quotes.csv`。
3. 核对币种、价格、MOQ、交期、付款条件和质量备注。
4. 展开供应商评分及每条来源 Evidence。
5. 核对风险 Finding 和系统生成的澄清问题。
6. 由项目负责人接受或修改 Finding。
7. 创建任务草稿，补充责任岗位、截止日期、交付物和验收标准。
8. 由负责人发布任务。
9. 在“任务与日报”提交交付说明和 Evidence 摘要。
10. 由负责人验收；缺材料时应驳回并要求补充。

完成条件：报价风险、人工选择理由、任务、交付 Evidence 和验收记录可在同一项目中查询。

## 4. 完整工作流 B 差评到改进复检

1. 导入 `reviews_before.csv`。
2. 核对批次时间范围、评价数量和去重结果。
3. 运行规则主题分析，展开包装破损 Finding。
4. 核对评价 ID、原文、样本数量、统计口径、缺失信息和替代解释。
5. 人工确认后创建改进任务并发布。
6. 提交包装测试或规范更新的交付 Evidence。
7. 由负责人验收任务。
8. 导入 `reviews_after.csv`。
9. 使用相同主题和统计口径执行复检。
10. 展示两批样本量、数量、占比、变化和非因果限制。

完成条件：可以从 Finding 回到原始评价，并继续追踪到任务、交付、验收和后续批次。

## 5. 异常演示

每次只演示一个异常。出现预期提示后返回正常数据，不要现场修改数据库。

### 5.1 报价缺少必填列

文件：`data/demo/supplier_quotes_missing_column.csv`

预期：导入在业务写入前停止，明确提示缺少 `currency`；不得创建报价批次。

### 5.2 报价包含混合币种

文件：`data/demo/supplier_quotes_mixed_currency.csv`

预期：系统提示 V1 不做实时换汇，要求统一 USD/EUR；不得生成不可比排名。

### 5.3 同一文件评价 ID 重复

文件：`data/demo/reviews_duplicate.csv`

预期：导入校验提示 `DEMO-DUP-001` 重复，不重复计数，不创建半成品批次。

### 5.4 评价缺少订单 批次和供应商关联

文件：`data/demo/reviews_missing_links.csv`

预期：评价可以按原文和主题统计，但页面明确显示无法关联订单、生产批次和供应商；系统不得根据相似名称生成虚假关联。

### 5.5 模型未配置或失败

保持 `.env` 中 `MODEL_API_KEY` 为空。

预期：页面显示模型未配置或规则降级；已导入评价保留，关键业务状态不写入无效模型结果。

## 6. 重启和恢复

### 正常重启

在运行 Streamlit 的终端按 `Ctrl+C`，然后执行：

```powershell
cd D:\hackson
.\.venv\Scripts\python.exe -m streamlit run app.py
```

SQLite 数据库和已导入记录会保留。

### 演示数据恢复

先关闭 Streamlit，再备份当前 `data/tradeloop.db`。数据库删除或替换属于破坏性操作，不在路演现场直接执行。需要全新演示库时，由甲在演示前于单独副本或临时目录执行初始化并验证。

重新运行：

```powershell
.\.venv\Scripts\python.exe scripts\seed_demo.py
```

脚本应可重复执行，不应重复创建已有演示项目、报价或评价批次。

### 页面异常恢复

1. 记录页面名称和错误提示。
2. 返回项目首页，确认当前项目仍已解锁。
3. 刷新浏览器一次。
4. 若仍失败，停止 Streamlit 后重新启动。
5. 不清库、不改生产式数据、不在现场粘贴密钥。

## 7. 模拟数据和能力边界

- `data/demo` 中数据均为模拟数据，不代表真实供应商、客户、订单或质量结论。
- 当前分类默认是规则基线，只有配置并实际调用合格的模型提供器后才能表述为真实 AI。
- 评价占比只表示当前评价样本中的占比，不是产品实际故障率。
- 前后批次变化只能描述趋势，不能单独证明某项措施有效。
- 访问码和演示角色用于黑客松演示，不是完整账号认证和企业级 RBAC。
- 规则库覆盖有限，`not_covered` 或“待确认”不能被表述为合规通过。
- 本地 SQLite 适合单机演示，不适合多人并发生产使用。
