## 1. 对外定位和保留范围

TradeLoop 是“证据驱动的跨境业务协作与本地化迭代工作台”。

目标用户：小型跨境电商团队。目标市场：美国、德国。主展示平台：Google Merchant Center 商品信息场景，复用现有平台规则；其他平台待扩展，不宣称已实现 Amazon/TikTok 全套适配。

统一主线：

```text
报价或评价 → 原始证据 → 人工确认的问题
→ 调查/改进任务 → 交付与人工验收
→ 已确认商品事实 → 英语/德语业务产出
→ 平台/条款校验 → 用户反馈第一轮 → V2
→ 用户反馈第二轮 → V3 → 再校验和人工确认
```

已有报价、差评、任务、日报、权限和复检继续保留。双语生成与反馈迭代是本轮必须补齐的核心；不增加人脸识别、自主多智能体或新前端框架。

关键限制：差评可以提出调查问题，不能直接变成对外商品承诺。只有人工确认的规格和经过验收的事实可进入生成上下文。没有证据时不得生成防漏、无毒、认证、质保、配送时效等承诺。

## 2. 六项硬性要求逐条兑现

| 评审要求 | 必须交付的实现 | 验收证据 |
|---|---|---|
| 1 核心业务场景 | 文档和页面说明用户、US/DE、目标平台、业务问题、触发、处理、输出及岗位 | 场景说明 + 页面实际操作 |
| 2 AI 应用/智能体 | 明确业务角色、任务、交互、目标市场知识、真实 DeepSeek 和本地校验 | 配置状态 + AiRun + 业务调用记录 |
| 3 本地化产出与两轮对话 | 中文事实输入，英语和德语产出；两次真实用户反馈驱动模型生成 V2、V3 | 双语 V1/V2/V3 + 两次反馈 + 模型记录 |
| 4 平台风格适配 | 平台产品信息字段、当地自然表达、单位和事实边界；超出知识范围标未知 | 双语内容 + 平台检查结果 + 人工语言检查 |
| 5 两类校验、两种反馈 | 平台商品信息政策 + 内部采购/合同完整性；文本批注/风险标记 + 可视化版本差异 | 两个规则场景结果 + 命中原文 + diff |
| 6 两个相关工作流 | 报价到任务验收；差评到验收/复检并衔接本地化迭代 | 同一候选版本的两条完整录屏和现场复演 |

第 5 项选择的“内部采购/合同完整性”明确标为企业内部标准，不冒充法律法规。德国消费者购买信息规则作为额外覆盖。规则无来源或不适用时显示待确认。

## 3. 两轮对话：不可缩减的实现标准

采用保守验收口径：首次生成不算一次反馈修订。必须完成两次用户反馈，最终得到三个版本。

### 首次生成 V1

- 用户输入中文商品事实、证据、市场和平台。
- 系统提供英语、德语目标选择，保存每种语言的首次产出。
- 模型输出结构化内容：标题、卖点、描述、事实引用、缺失信息和人工审核项。
- 程序运行适用规则，显示命中片段和风险建议。

### 第一轮反馈：V1 → V2

- 用户在页面输入真实文字反馈，例如“突出已确认的容量，删除没有证据的性能承诺，调整为自然的当地商品语气”。
- 请求携带已确认事实、V1、用户反馈和适用规则检查结果。
- 模型生成 V2；保存原始反馈、父版本、Prompt 版本、AiRun 和输入哈希。
- 展示 V1/V2 差异，重新运行规则。

### 第二轮反馈：V2 → V3

- 用户再次输入反馈，例如“保留已核实卖点，简化标题、压缩重复表达，并补充当前确有证据的尺寸”。
- 请求携带同一事实边界、V2、两轮反馈历史及校验结果。
- 模型生成 V3，父版本必须指向 V2；不覆盖 V1 或 V2。
- 展示 V2/V3 差异和三版本时间线，重新校验。

### 强制通过条件

- [ ] 英语和德语各有 V1、V2、V3，共六份产出；可使用同一份已确认商品事实。
- [ ] 两次反馈分别保存；第二次确实基于 V2，而不是重启一条 V1。
- [ ] 页面反馈触发真实模型，不能用人工粘贴内容冒充模型迭代。
- [ ] 每个版本可查市场、平台、来源事实、父版本、Prompt 和运行记录。
- [ ] 刷新和重启后版本链仍然存在。
- [ ] 模型失败不创建成功版本，已有版本不丢失，允许人工重试。
- [ ] 不能只按版本数量宣称有效迭代；人工核对每次反馈是否被落实。
- [ ] 新反馈要求补造事实时拒绝或标记待确认。

目前 `create_v2_generation` 只允许父版本为 V1，页面也只有人工 V1/V2，必须扩展。保留旧函数及人工录入路径以兼容现有测试；新增通用模型生成与修订路径。是否新增数据库字段先由甲检查，必要时新增迁移，不能改写 0001/0002 历史。

## 4. 阶段任务、文件与甲乙分工

### M0：环境和基线同步，立即执行

甲：审核并提交 `.gitignore`、`requirements-lock.txt`、`services/model_provider.py`、`tests/test_model_provider.py` 和本轮新增文档。确认 `.env` 不在提交内。

乙：按 `docs/PARTNER_ENV_SETUP_PROMPT.md` 安装环境，返回 HEAD、Python、测试和启动结果。

验收：两台电脑代码 HEAD 一致；本机最新离线基线为 176 项测试和 Ruff 通过。DeepSeek 最小联网验证已成功，耗时 673ms；这不替代业务分类和生成验收。模型 Key 各自保存在本机。

### M1：真实评价业务验证 + 生成 V1 最小闭环

甲负责：

- `services/review_ai_service.py`：核对真实分类、统计、原文引用、失败不污染及审核状态。
- `core/schemas.py`：新增本地化结构模型和事实引用校验。
- `services/localization_service.py`：新增受成员权限约束的模型 V1 生成及持久化。
- `services/ai_service.py`：复用现有运行审计，不重复实现模型客户端。
- `prompts/`：增加版本化本地化 Prompt，约束事实、语言和平台。
- `tests/test_localization_workflow.py` 及新增服务测试：验证字段、引用、权限、错误和持久化。
- `core/models.py`、`migrations/` 仅在缺少必要关联字段时修改，提前通知乙。

乙负责：

- `pages/05_本地化与校验.py`：中文事实输入、市场/平台选择、生成按钮、双语产出、证据和缺失项。
- `pages/04_差评改进.py`：明确已审核发现与可对外使用事实的区别；需要服务接口时向甲提出字段需求。
- 页面测试：覆盖未配置、调用失败和生成成功状态，不调用真实 API。

联合验收后分别 commit、互审，合并集成分支。先跑通一个市场 V1，再扩展第二市场，避免一次合并大改。

### M2：两轮真实反馈和 V3，最高优先级

甲负责 `services/localization_service.py`、Schema、Prompt、版本查询和相关测试，完成任意合法父版本的追加、AiRun 关联和跨项目拒绝。

乙负责 `pages/05_本地化与校验.py`、页面测试，完成反馈输入、提交防重复、版本选择、V1→V2→V3 时间线和 diff。现有 `children[parent_id]` 展示需要适配多级链路，不能只展示一个 V2。

共同接口先确认：项目/用户、父版本 ID、反馈文本、目标市场/平台、生成结果、来源引用、运行 ID、错误状态。乙不要自行在页面拼接一套业务状态机。

验收：两种语言各完成两次实际反馈修订，六份结果及完整历史可重新打开。离线测试验证逻辑，受控真实调用验证提供器；两类证据分别记录。

通过后共同合并集成分支并交换新 HEAD。此阶段未通过，不能进入最终冻结。

### M3：规则与反馈方式整合

甲负责 `services/rule_service.py` 与必要规则测试；核对规则来源、版本、适用场景及缺失处理。更新 `data/rules.json` 前通知乙，不能把未经核实的新规则加入正式结论。

乙负责本地化页结果展示、命中原文批注、风险标记和版本差异。为两类检查各准备一份正常/异常示例。

验收：同一展示过程能看到平台政策检查和条款完整性检查，并展示风险/文本反馈与可视化对比。每次修订重新校验，不能沿用旧版结果。

### M4：真实公开数据与最终复演

甲负责数据转换服务/脚本与可重复统计；乙负责来源说明、样本包和演示脚本。数据应新建 `data/evaluation/` 或独立本地目录，不覆盖原模拟 CSV。

先选 30～50 条许可明确的公开评价，另留一组未参与 Prompt 调整的测试样本；两人先按主题字典人工标注并解决分歧，再评价模型。记录主题准确情况、原文引用有效率、缺关联是否正确保留、去重、失败、耗时及调用开销。星级不能直接当作问题类别标签。

Amazon Reviews 2023 可验证评价分类和引用；Olist 可验证订单/评价/卖家/配送关联。选择前核实许可与下载条件，保留来源、原始 ID、哈希、转换规则及标注版本。不能称为中国出海企业内部数据，也不能将数据集卖家直接映射为本项目供应商。

最终共同检查 `docs/BATCH_ACCEPTANCE.md`，更新 README、状态文档、运行手册、海报和讲稿；新电脑启动、双语两轮迭代、两条流程、异常及规则检查全部复演后才合并 main、创建 `hackathon-final`。

乙：`pages/`、页面测试、`data/demo/`、`deliverables/`、运行手册和演示内容。
