## 三、必须用户提供真实 API 后完成

配置前先阅读 [模型 API 本地配置与安全检查](MODEL_API_SETUP.md)。默认离线命令为：

```powershell
python scripts\check_model_api.py
```

截至本轮未配置环境，实际离线结果是 `configured=false`、`live_verified=false`、`missing=MODEL_API_KEY,MODEL_NAME`，退出码为 `1`。这是配置前的安全默认状态，不是故障；用户以后填写配置后应以新一次检查为准。任何自动流程都不得添加 `--live`。

### 1. 用户需要提供或确认

以下值只写入本机 `.env` 或部署 Secret，不得粘贴到聊天记录、测试文件、截图、日志、Markdown 或 Git：

| 项目 | 用户填写/确认 | 安全要求 |
|---|---|---|
| `MODEL_API_KEY` | [ ] 已在本机或部署 Secret 配置 | 不记录真实值，不提交 Git |
| `MODEL_NAME` | [ ] 已提供准确模型标识 | 验收记录可以写模型名，但不能写密钥 |
| `MODEL_BASE_URL` | [ ] 已提供 OpenAI-compatible 服务地址 | 只记录经过确认的地址；不得猜测供应商 |
| 是否允许一次 live 测试 | [ ] 允许 / [ ] 不允许 | 未明确允许时不得发起真实请求 |
| 测试数据范围 | [ ] 仅使用脱敏小样本 | 不发送姓名、电话、地址、访问码或无关业务字段 |

预计只需要一次受控 live 测试，使用最小、脱敏的评价样本。若供应商不支持当前使用的严格 JSON Schema / chat completions 兼容格式，应记录为兼容性失败，不得通过改写结果或伪造响应宣称成功。

### 2. 获得授权后的执行门禁

- [ ] 用户已经明确允许本次真实请求和预计费用。
- [ ] `.env`、终端历史、录屏和日志不会暴露 `MODEL_API_KEY`。
- [ ] 输入只包含完成分类所需的评价 ID、脱敏文本和最少业务字段。
- [ ] 当前分支、数据库备份和测试基线已记录。
- [ ] 测试期间不自动发布任务、不自动判责，模型 Finding 保持待人工审核。
- [ ] 确认 live 命令只能由操作者手动执行一次，启动、CI、测试和演示脚本绝不自动运行 `--live`。

### 3. live 验收证据

以下项目必须全部有证据，才能把状态改成“真实模型联网已验证”：

- [ ] 真实调用命令或页面操作正常结束，进程退出码为 `0`，没有未处理异常。
- [ ] 验收记录包含实际 `MODEL_NAME`，但不包含 API Key。
- [ ] 记录调用耗时，并与 AiRun 的 `latency_ms` 对照。
- [ ] 模型响应通过本地 Pydantic / 结构化 Schema 校验；无效结构不得写入关键业务状态。
- [ ] 数据库生成一条成功状态的 AiRun，记录 Prompt 版本、输入哈希、模型名、状态和耗时。
- [ ] 每个重要 Finding 的评价 ID 和原文引用通过本地证据校验，不能引用不存在或跨项目的评价。
- [ ] 模型结论保持为待审核假设，由人工接受、修改或驳回；模型不能自动判定责任。
- [ ] 移除或故意使用无效 API Key 后，系统安全降级到未配置/失败状态，保留已导入数据，不写入伪成功结果。
- [ ] 401、429、超时或服务错误只显示脱敏、可操作提示，不记录上游私密响应。

### 4. 不能作为 live 证据的内容

- fake transport、monkeypatch、录制响应、固定 JSON fixture 或模拟 HTTP 服务。
- 仅运行 `tests/test_model_provider.py`、`tests/test_ai_service.py` 或其他离线单元测试。
- 规则分类成功、页面显示 AI 按钮、AiRun 模拟记录或手工插入数据库行。
- 没有模型名、耗时、结构校验、AiRun 和证据引用记录的截图。

如果用户不提供真实 API 或不允许 live 请求，项目仍可按规则降级完成演示，但必须保持“真实模型联网未验证”的表述。
