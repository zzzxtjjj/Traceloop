# 欢迎使用 TradeLoop

点击下面的标题展开教学，随时从左侧返回。每个板块都说明准备什么、怎样操作、如何判断完成以及遇到问题怎么办。

**首次体验：**项目首页 → 选择演示用户 → 加载演示项目 → 输入访问码 `demo2026` → 报价决策或差评改进。先用模拟资料练习，再导入自己的资料。

**处理差评的完整路线：**导入评价 → 分析并查看原文 → 人工确认问题 → 发布任务 → 提交材料 → 人工验收 → 比较后续评价。

## 1 · 项目首页：先确定谁在处理哪个项目

**用途：**创建项目、选择身份、进入项目和添加成员。所有业务页面都围绕左侧当前项目工作。

**演示步骤：**

1. 选择本地演示用户。需要负责人操作时选择演示负责人。
2. 点击“加载演示项目”；已经加载过则选择现有项目。
3. 使用 `demo2026` 解锁演示项目，自己的项目使用创建时设置的口令。
4. 确认左侧显示正确项目、用户和岗位，再进入其他页面。

**创建自己的项目：**先创建本地用户，再创建项目并填写商品、目标市场和访问口令。创建者成为负责人；负责人在成员区域添加其他已有用户并指定岗位。创建用户不会自动加入项目。

**完成标志：**能进入项目且岗位正确。切换用户后，可见项目与可执行操作应与成员身份一致。

**常见问题：**没有项目可选，确认是否已加入；口令错误，检查选择的项目；按钮不能点击，确认岗位权限。知道口令不代表具有成员资格。本地身份选择用于演示，不是生产登录。

## 2 · 报价决策：比较供应商，并核对风险依据

**准备：**报价 CSV，练习文件是 `data/demo/supplier_quotes.csv`。按页面模板准备字段，当前入口不是任意 Excel/PDF 文档解析。

1. 在“导入报价”上传 CSV，检查预览和字段提示，确认后导入。
2. 打开“比较与排名”，选择批次，查看价格、起订量、交期和付款条件。
3. 调整比较权重，理解哪些条件影响排名。
4. 展开来源依据与待澄清事项，核对原始行、字段和值。
5. 负责人选择供应商并填写理由，确认采购决定。

**完成标志：**决定有理由，风险能回到原始报价。排名只是参考，不自动选择供应商。

**常见问题：**缺字段先补 CSV；不同币种不能无依据直接排名；重复文件无需再次导入。没有运费、税费或贸易条件时，不要把排名当完整到岸成本，也不要补造供应商承诺。

## 3 · 任务与日报：执行、提交材料、等待验收

**准备：**已发布的任务。暂无任务时，先去“差评改进”审核问题并发布改进任务。

**执行人步骤：**

1. 展开任务，阅读岗位、依赖和验收标准。
2. 更新执行状态：`todo` 为待执行，`doing` 为进行中，`blocked` 为被阻塞。
3. 填写“交付说明”和“验收材料/可核查引用”，例如测试编号、检查记录或文件位置。
4. 点击“提交人工验收”。提交不代表完成，等待有权限的审核人处理。

**负责人步骤：**在“待验收交付”检查材料，对照标准选择“验收通过”或填写意见后“驳回补充”。执行和审核受岗位及审核限制约束。

**日报：**关联任务，填写今日完成、引用位置、阻塞事项和下一步计划。“风险复盘”用于查看阻塞、逾期与资料缺失提醒。

**完成标志：**材料已被人工验收，任务才算完成。日报不替代交付证据；没有日报也不代表员工没有工作。

**常见问题：**不能提交先检查任务是否发布、岗位是否匹配、材料是否齐全。不能审核时检查当前身份与审核限制。

## 4 · 差评改进：从客户原话到改进任务

**准备：**评价 CSV。练习使用 `data/demo/reviews_before.csv` 和 `reviews_after.csv`，两者都是模拟数据。

1. 上传评价文件，填写批次名称，点击“校验并导入”。
2. 选择批次，第一次练习可选“规则分类”；已配置模型时可选“真实 AI 分类”。
3. 点击“运行所选分类”后等待。真实 AI 会发送必要评价字段并可能计费，不要连续点击。
4. 展开问题，检查说明、评价数量、客户原文和缺失信息。无需记住模型编号，技术详情放在“分析记录”中。
5. 判断合理选“接受”；需调整则填写修改结论和备注后“修改并接受”；不成立则说明理由并“驳回”。
6. 从已确认的问题创建任务草稿，由负责人确认发布。
7. 在“任务与日报”执行、提交证据并完成人工验收。
8. 有新评价后再导入，选择前后批次和问题主题，点击“比较两批评价”。

**完成标志：**问题能追溯原文，改进有任务和验收，后续结果展示数量、占比和样本量。

**如何理解结果：**评价占比不是全部商品的故障率；下降不能单独证明改进造成效果。没有可靠订单、批次或供应商信息时，不能归责。

**常见问题：**重复评价会跳过；模型失败时看清是否降级为规则分类。空批次或缺字段先修正 CSV。不要把规则结果称为真实 AI 判断。

## 5 · 本地化与校验：记录文案修改，并检查规则

**当前页面支持人工 V1、反馈与 V2，以及独立规则检查。**真实模型英德文案、两次反馈修订已完成后端复验，但尚未接入此页面；这里暂时没有自动生成 V3 的按钮。

**记录文案：**

1. 打开“文案与修改记录”，选择美国英语或德国德语。
2. 填写该语言第一版内容，点击“保存人工 V1”。
3. 选择 V1，填写修改反馈和第二版内容，保存人工 V2。
4. 查看版本链中的原文、修改意见、第二版和差异。已有 V2 的 V1 不会被重复覆盖。

**检查规则：**打开“独立规则校验” → 选择市场和场景 → 粘贴商品标题、消费者购买信息或采购条款 → 运行检查 → 核对风险、命中文字、建议、来源和版本 → 修改后重新检查。

**完成标志：**文案修改有记录，问题对应原文和规则来源。平台政策、消费者信息要求、企业内部标准是不同类型，不能混称法律结论。

**常见问题：**没有命中不等于全面合规；没有可靠来源或规则未覆盖时需要人工确认。设置中的界面语言不会自动翻译这里的业务内容，目标市场需另选。

## 6 · 设置：选择界面语言和 AI 服务

**语言：**可选简体中文、English、Deutsch。已覆盖界面文字随之切换；未覆盖提示回退中文。评价原文、输入和历史记录保持原语言。

**继续用现有 DeepSeek：**本机配置已就绪时保持“当前使用：本机环境配置”，不用重新填密钥。

**更换 AI：**

1. 选择服务商，从该账户控制台复制接口地址和模型名称。
2. 输入该厂商自己的 API 密钥，不能复用其他厂商密钥。
3. 点击“应用设置”。保存不会调用模型；下一次业务分析才使用当前设置。
4. 回到差评页，用少量非敏感评价确认成功或失败状态。
5. 想回到本机配置，点击“恢复本机配置并清除会话密钥”。

**保存范围：**仅当前浏览器会话，不写入 `.env`，不影响同伴；会话结束可能丢失。不要截图或发送真实密钥。

**常见问题：**只有 DeepSeek 做过真实联网验证，其他服务需各自验证。失败先核对模型权限、地址、余额和网络，不要反复发送请求。

## 7 · 常用术语和两人协作

- 原始依据：客户原文、报价字段或交付材料等可核查记录。
- 待审核问题：规则或模型提出的问题，需要人工确认。
- 任务草稿：尚未正式发布，不能当作已执行工作。
- 复检：用相同口径查看后续数据，不自动证明因果。
- 甲负责服务、数据、AI和权限；乙负责页面、教学和演示材料。共享代码，不共享密钥、数据库和虚拟环境。
