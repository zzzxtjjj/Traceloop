## W0 · 对齐与开发前门禁

- [ ] 甲乙核对Git状态与同一基线；保存已有修改，不盲目切分支。
- [ ] 明确独立账号的可信身份方案，不能只信任前端传入user_id。
- [ ] 确认岗位、权限、对象ID、分页、状态和幂等契约。
- [ ] 解释每张新增表的必要性、关联、空值、迁移和旧数据处理。
- [ ] 用户确认后才进入实现。

## W1 · P0：项目、身份与消息

- [ ] 项目工作空间七个区域与现有报价/评价/本地化入口衔接。
- [ ] 两个独立账号具有同项目成员关系；非成员另设测试账号。
- [ ] sender由可信身份派生；消息持久化、稳定分页、手动刷新。
- [ ] 回复和附件不能引用跨项目对象。
- [ ] 重试同一发送请求不重复写入；相同内容的新消息仍可发送。
- [ ] 旧角色兼容；新增岗位与实际授权分开。

## W2 · P0：文件

- [ ] 复用/扩展Artifact；记录上传人、类型、哈希、时间与解析状态。
- [ ] 原件落盘，数据库不直接存文件二进制。
- [ ] 大小/MIME/路径穿越/压缩炸弹检查；损坏文件明确反馈。
- [ ] 成员可按授权上传、查看和下载；非成员、停用成员拒绝。
- [ ] 重复上传明确提示，不泄露其他项目的同哈希文件。
- [ ] 解析失败保留原件；写盘与事务异常无半成品可用记录。

## W3 · P0：文件理解与岗位需求

- [ ] PDF文本页、DOCX段落/表格、XLSX工作表/行列、CSV行列和TXT行号定位有测试。
- [ ] 图片/扫描件支持状态如实标记；未实现OCR不假装解析成功。
- [ ] 文档要求引用原文件、提取版本和可验证原文。
- [ ] 模型提取字段完整，置信度不等于真实性。
- [ ] 注入指令不能改变权限或读取其他项目。
- [ ] 日期/岗位/资料缺失与冲突保留待确认；不虚构规格。

## W4 · P0：任务建议与人工发布

- [ ] 任务草稿包含说明、岗位、建议人员、优先级、截止、依赖、交付物和验收标准。
- [ ] 来源需求和Evidence正确关联，建议人选仅限实际成员。
- [ ] 人工Accept/Modify/Reject留痕，发布另需授权确认。
- [ ] 重复建草稿/发布有幂等保障；依赖循环被拒绝。
- [ ] 缺交付材料不能验收，原有质量改进闭环不回归。

## W5 · P1：汇报与复盘

- [ ] 优先复用DailyReport，记录作者、日期、完成/待办任务、阻塞、支持和计划。
- [ ] 用户自报完成与实际验收状态分开。
- [ ] AI复盘基于时间窗和实际提交，条条引用任务/汇报/证据。
- [ ] 逾期与依赖由程序检查，无资料不编造进度。
- [ ] 文件历史版本、基础通知按确认方案实现。
