## 9. 每日同步与什么时候commit

1. 每人开始前检查自己的branch/HEAD/status；不要直接覆盖对方未提交修改。
2. 完成一个可检查小模块，跑相关测试，**各自提交自己负责的明确文件**，不用等两人同时点commit，也不要git add .夹带密钥/数据。
3. 每个M节点由指定整合人审阅并顺序整合两边提交；冲突交回文件责任人确认，不能直接选ours/theirs整片覆盖。
4. 联调通过后记录共同SHA、实际测试命令与结果；另一人工作区安全后同步该SHA，再开始依赖下一节点的工作。
5. 节点未通过不必停止独立开发；未通过部分留在功能分支，禁止标成已合并已验收。
6. Schema或共享文件签名变化提前通知另一人；新增映射优先，破坏变更必须明确版本。
7. 本轮没有执行任何commit/push/merge/tag；以上为双方未来执行步骤。
