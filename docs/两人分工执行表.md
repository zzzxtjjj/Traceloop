## 五、什么时候两个人一起合并和 commit

你们不需要同时敲一个 `git commit`。正确方式是：

1. 两个人分别在自己的分支完成小任务并提交。
2. 推送到 GitHub。
3. 开 Pull Request。
4. 另一人验收代码和页面。
5. 两边都通过后合并到 `main`。
6. 合并后的 `main` 就是你们的“共同 commit 同步点”。

需要完成：

```text
甲：A1 真实模型服务
```

- [ ] 模型输出能通过 Schema。

- [ ] 模型失败不会写入 Finding。

## 七、每天开始和结束时怎么同步

### 每天开始

```powershell

git pull --ff-only origin main
git checkout <自己的分支>
git merge main
```

### 完成一个小模块后

```powershell
python -m pytest -q
python -m ruff check core services pages scripts tests
git status --short
git add <只添加本模块文件>
git diff --cached
git commit -m "feat: <本次真正完成的结果>"
git push
```

### 开 Pull Request 前

- [ ] 分支已经合并最新 `main`。
- [ ] 测试全部通过。
- [ ] 没有 `.env`、数据库、上传文件和真实客户数据。
- [ ] PR 写清楚完成内容、修改文件、测试结果和限制。
- [ ] 指定另一人为 reviewer。

### 合并后

两个人都执行：

```powershell
git checkout main
git pull --ff-only origin main
git rev-parse HEAD
```

两边提交哈希相同，才算同步完成。

## 八、禁止事项

- 不要两个人同时修改同一个文件。
- 不要直接在 `main` 上开发新功能。
- 不要使用 `git push --force` 推送共享分支。
- 不要使用 `git reset --hard` 处理合作冲突。
- 不要提交 `.env`、SQLite 数据库或 API Key。
- 不要为了演示伪造真实供应商、订单、价格或合规结论。
- 不要把规则分类说成真实 AI。
- 不要把前后评价变化说成已经证明改进有效。
